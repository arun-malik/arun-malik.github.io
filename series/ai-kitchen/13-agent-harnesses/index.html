CHAPTER 14 / 16 · Bound the execution

What keeps the agent inside the kitchen?

Sep 28, 2026 · 4 min read

Series · AI · Foundations

Builds on chapter 13. Specific dependencies are in the concept map.

An instruction saying “be careful” cannot limit a program's file access. The surrounding software needs to decide what the agent can see, what it can do, and when it must stop.

The equipment around the model

An agent harness is the surrounding execution scaffold that enables and controls an agent's work. Here the term includes context assembly, tool access, state handling, limits, and observation of the run. Teams use the word with different boundaries, so ask what a particular harness actually provides.

The model is like one component on a workbench. The harness supplies the holders, connections, controls, and stop mechanism. It is software around the model, not another name for the model's weights.

Context engineering is the work of selecting, arranging, and maintaining useful information for model invocations. It includes instructions, retrieved evidence, tool descriptions, and progress notes. A tidy worktop helps the task, but removing the one important warning just to make it smaller can make things worse.

A tool registry is a maintained collection of available tool descriptions and interfaces. Exposing a small relevant set can reduce confusing choices. Removing a tool from the visible list is not a substitute for blocking unauthorized access at the execution boundary.

Enforce a boundary

Least privilege gives a component only the access required for its task. Our menu-writing assistant needs to read recipe notes and save a draft. It does not need to edit prices or send messages to customers.

A sandbox is an execution environment that restricts some interactions with the surrounding system. It may limit files, processes, or network access. Think of a separated preparation station with controlled supplies, not an invincible force field.

Sandbox boundaries depend on configuration and implementation. A sandbox allowed to contact an external service can still send information there. Permissions, network rules, isolation, and review need to work together.

Prompt injection is an attempt to make instructions embedded in untrusted content redirect the system's behavior. A recipe note might contain text telling the assistant to ignore its task or reveal unrelated records. Reading a note should not grant that note authority.

Treat retrieved text and tool outputs as data with a known origin. Keep secrets out of unnecessary context, restrict actions independently, and test the boundaries. A stronger warning sentence alone is not a complete defense.

Stop, retry, or ask

Execution limits bound work by resources such as time, cost, steps, or tool use. Limits must be enforced by the application. An agent that repeatedly searches the same empty drawer needs to stop and explain the gap.

A retry repeats an operation after failure. A fallback switches to an alternative behavior when the main path cannot finish. A failed read can sometimes be retried; an uncertain write needs a state check or duplicate protection first. A useful fallback may be a plain error message rather than another model.

Human review places a decision with a person before a consequential step proceeds. A pause must preserve the proposed action and its context, then resume only after a relevant approval or correction. A person cannot meaningfully approve an unspecified action or an outcome already executed.

Keep a record without keeping everything

A trace records the observable steps of a run, such as tool calls, responses, timings, and errors. Logging stores operational events for diagnosis and monitoring.

These records help explain where a run failed. They do not necessarily expose all internal model computation, and a generated explanation is not a faithful readout of it. Redact unnecessary personal data and credentials, control access, and set retention periods.

The assistant promises never to change prices. Is the boundary complete?

No. Remove price-changing capabilities when they are unnecessary and deny unauthorized changes in the application and service. The promise may guide behavior, but enforcement belongs outside the generated text.
