Ask for a name for our cafe's new soup. “Garden bowl” and “Green afternoon” could both be acceptable. Ask whether today's cafe is open, and variety is no substitute for evidence. Generation settings affect choices, not the truth of the world.

What the model receives

A prompt is input used to guide a model's response. It can contain a request, examples, instructions, and supporting information. “Describe this soup in one short sentence” gives a clearer task than “do something with soup.”

Messages are structured pieces of an interaction, often marked with roles such as user, assistant, or tool. Instructions tell the system what behavior is wanted. Applications may supply higher-priority instructions separately from the user's request; the exact roles and precedence depend on the system.

Context is the information available to the model in a particular invocation. It can include instructions, selected conversation history, retrieved notes, and tool results. The model does not automatically receive everything displayed in an application's interface or everything stored on a computer.

A context window is the supported capacity for an invocation's sequence, usually measured in tokens for text models. Input and generated output consume capacity according to the model and service's rules. Staying below a limit does not guarantee that every detail will be used correctly. There is no universal percentage at which all models suddenly fail.

One next-token choice

Logits are raw numerical scores a model produces for possible next tokens. A conversion such as softmax turns these scores into a probability distribution: nonnegative shares across candidates that sum to one.

For an invented three-token vocabulary, suppose the next-token shares are soup 0.6, salad 0.3, and cake 0.1. These numbers describe possible continuation choices in this toy example. They are not measurements from a model, and 0.6 does not mean a sentence about soup is 60 percent true.

Decoding here means the procedure for selecting output tokens from model scores. Greedy decoding picks a highest-scoring next token. Sampling draws a choice using a probability distribution, so a less likely token can sometimes be selected.

After selecting one token, a common autoregressive generator appends it and calculates the next choice. This continues until a stopping condition, such as an end token or output limit. Selecting each locally likely token does not guarantee the globally best answer. “Decoding” can also mean converting token IDs back into readable text; context tells you which use is intended.

Two knobs, no truth switch

Temperature is a decoding setting that changes how concentrated next-token probabilities are. With the usual positive-temperature transformation, lower values emphasize score differences and higher values flatten them. It changes the selection distribution, not learned weights.

Imagine a raffle with unequal piles of tickets. Temperature changes how uneven the piles are. It does not check whether the prize description is accurate. Supported values and behavior vary by model and implementation. A hosted service's zero-temperature option is not a universal guarantee of identical output across runs, versions, or serving conditions.

Top-p keeps a smallest set of highest-probability candidates whose cumulative probability reaches a chosen cutoff, then samples from that restricted set. With our toy shares and a cutoff of 0.8, soup and salad are kept because 0.6 + 0.3 = 0.9. Cake is excluded; the kept shares are renormalized to two thirds and one third.

Changing several knobs at once makes it harder to see which change helped. Some models do not expose these settings at all.

A fluent answer can still be invented

A hallucination is generated content that is false or unsupported while being presented as an answer. A model might invent our cafe's opening hours because that kind of sentence fits the request.

Uncertainty is the possibility that an answer or estimate is wrong or insufficiently supported. A confident tone is not a reliable measurement of it. Asking the model for a confidence number does not automatically produce a calibrated probability.

When the answer depends on today's opening hours, supply trustworthy current information or have the application look it up. If the evidence is absent or conflicting, admitting that gap is more useful than polishing a guess.

Our soup token has probability 0.6. Is the recipe claim probably true?

That number concerns the next token under the toy distribution. It does not measure the truth of a recipe claim. Evidence and task-specific evaluation answer a different question.
